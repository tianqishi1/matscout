# MatScout 产品设计方案（PRD）
版本：v0.1 MVP ｜ 日期：2026-11-23 ｜ 状态：开发中

## 1. 背景与问题
材料科研人员在「提出想法 → 立项」之间最大的隐性成本是**查新**：
- 想法是否已被做过？最接近的工作是什么？差异点在哪？
- 通用 LLM 直接回答不可靠：Ai2 NoveltyBench 证明 LLM 自评新颖性不可靠；Stanford 百人盲评显示 LLM 想法新颖性高但可行性偏低（ideation-execution gap）。
- 现有工具（MatChat/SciMaster/Elicit/Undermind）强在「检索与综述」，但**没有把「想法 → 最接近工作 → 差异点 → 可行性」做成结构化、可溯源、可复核的查新闭环**。

## 2. 定位
**材料课题组的事实核查型科研副驾驶（co-scientist）**。
- 不替科学家做科学判断；把每一步变成可溯源、可核查的证据链。
- 形态：**Skill（领域 SOP）+ MCP 工具层（确定性能力）**，寄生于宿主 agent（Codex/Claude/Bohrium 等），不做独立全流程 agent。
- MVP 只做一个楔子：**想法查新卡片（Novelty Card）**。XRD 解读、证据链写作、审稿修订为后续版本。

## 3. 目标用户与场景
- 主要用户：材料方向研究生/博士后/PI；场景：开题查新、基金申请前查新、论文投稿前「相关工作」自查、组会想法评估。
- 典型输入：一段中文或英文的想法描述 + 领域标签（如「钙钛矿太阳能电池」「高熵合金」「固态电解质」）。
- 典型输出：一张 Markdown 查新卡片（见 §5）。

## 4. 核心用户流程
1. 用户向宿主 agent 描述想法（或说「帮我在 XX 领域找方向」→ 先走检索再收敛想法）。
2. Skill 引导宿主：澄清想法边界 → 构造中英文检索式 → 调 `search_literature`。
3. 对候选最接近工作逐条 `verify_citation`（服务端强制：未核验文献不得进入结论）。
4. `find_closest_work` 给出透明相似度排序（词面重合 + 匹配词列表，可解释）。
5. 宿主按 SOP 撰写差异点/可行性/风险，`save_novelty_assessment` 提交；**服务端校验每条差异点必须引用已核验文献 ID，否则拒绝**。
6. `render_novelty_card` 生成卡片 → **人工复核门**：用户确认/修改后才算定稿。
7. 全过程写入本地证据库（SQLite），卡片附录含证据 ID、检索式、时间戳、AI 使用披露。

## 5. 查新卡片规格（核心交付物）
- 想法描述（原文 + 规范化表述）
- 查新结论：四档 verdict（高度新颖 / 增量创新 / 已有近似工作 / 高度重复）+ 置信度 + 一句话依据
- 最接近工作 Top-5：标题/作者/期刊/年份/DOI 链接 + 重合点 + 差异点（每条挂证据 ID）
- 可行性清单：设备、算力、前驱体/原料、时间尺度、关键风险（宿主填写，标注「待专家确认」）
- 不确定项与检索局限（数据库覆盖、时间窗、语言）
- 证据附录：检索式、来源、检索时间、证据 ID 列表
- AI 使用披露（固定文案）+ 人工复核状态

## 6. 非目标（MVP 明确不做）
- 不做论文代写/自动投稿/自动回复审稿人（伦理红线，见 AGENTS.md）。
- 不做实验仪器控制、不做 DFT 计算执行（P1 以 MCP 工具接入）。
- 不做多用户 SaaS/账号体系；单机本地证据库。
- 不抓取付费墙全文；只用开放元数据与摘要（OpenAlex/Crossref）。
- 不内置商业软件/数据（VASP、ICSD 等许可问题）。

## 7. 成功指标（MVP 验收）
| 指标 | 目标 | 测量方式 |
|---|---|---|
| 引用幻觉率 | 0（卡片中所有 DOI 均经 API 核验） | 服务端硬门 + 抽查 |
| 已知相关工作召回 recall@10 | ≥ 0.8（评测集） | evals/run_eval.py |
| 单想法查新耗时 | ≤ 5 分钟（含人工复核前） | 演示计时 |
| 证据可溯源率 | 100%（每条结论挂证据 ID） | 卡片结构校验 |
| 专家可用性 | 2-3 个课题组试用后「愿意继续用」 | 后续人工访谈 |

## 8. 路线图
- P0（本 MVP）：查新 skill + MCP（检索/核验/证据库/卡片）+ 评测集。
- P1：XRD 解读 skill（pymatgen/COD 物相指认 + 与假设一致性校验）；计算工具 MCP 接入（Materials Project/CHGNet）。
- P2：证据链手稿工作台、审稿修订闭环；多用户证据库与私有化部署（届时升级为独立 agent 壳）。

## 9. 商业模式
免费 skill 引流（Codex/Claude/Bohrium 生态分发）→ 付费能力层（检索增强 API、算力转售）→ 课题组/院系私有化订阅。

## 10. 风险与对策
- 检索覆盖不足 → 明示局限；P1 增加 Semantic Scholar/arXiv 源。
- 词面相似度漏掉语义近似 → 卡片强制「检索局限」节；P1 引入 embedding 重排。
- 宿主模型不遵守 SOP → 关键校验下沉服务端（引用核验门、差异点引用门）。
- 学术伦理 → AGENTS.md 硬约束 + 卡片固定披露文案 + 人工复核门。
